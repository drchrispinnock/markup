# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Markup is a native macOS plain-text editor, written in Swift with AppKit, that will eventually edit Markdown. The scope ends there: the document stays plain text and the editor won't do anything beyond that.

## Building, running and testing

It is a Swift Package (no Xcode project), built with the Command Line Tools:

- `swift build` builds the app.
- `swift run` builds and launches it as a bare executable. Debug builds embed `img/Markup.png` in the executable's `__TEXT,__markup_icon` section (`Package.swift`), and `DevelopmentIcon` draws it as the app icon when there's no app bundle, cropped and clipped the way the icon script does it.
- `scripts/build-app.sh` makes `build/Markup.app`: a release build, `Info.plist`, and `AppIcon.icns` generated from `img/Markup.png` by `scripts/make-icon.swift`, all ad-hoc signed. The icon script makes the artwork's white surround transparent and clips it to exactly an 824×824 rounded rect (radius 185) at (100, 100) on a 1024 canvas. macOS 26 shows any other outline shrunk onto a grey plate.
- `swift test -Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing` runs all tests.
- Add `--filter ListEditorTests/tabNestsAndShiftTabUnnests` to run a single test.

The `-plugin-path` flag is needed: the Command Line Tools keep the Swift Testing macro plugin in `plugins/testing/`, and the build doesn't reliably search there. Without the flag, test builds fail intermittently with "plugin for module 'TestingMacros' not found".

The machine has only the Command Line Tools, not full Xcode. They lack SwiftUI's macro plugins, so `@State` and other SwiftUI macros fail to compile. That is why the UI is plain AppKit; don't introduce SwiftUI unless full Xcode is installed.

## Targets

- `MarkupCore` is pure Swift with no AppKit. `BlockStyle` is the line styles (raw value = heading level, 0 = paragraph, -1 = code, -2 = table cell). `ListItem` (level + `ListMarker`: bullet / unchecked / checked) is a list line. `MarkdownCodec` converts Markdown to and from `[Line]`, losslessly. It recognises `#`/`##`/`###` + space, and `- `, `- [ ] `, `- [x] ` with two spaces of indent per level. Lines between a ```` ``` ```` fence (with any info string, such as a language) and the next line of exactly as many backticks are `.code` lines kept verbatim; the first carries the `CodeFence` so it is written back as it was, and the fence is lengthened if a line inside would close it. GFM tables (`MarkdownTable`: a header row and a delimiter row with the same number of cells, then rows up to a blank line, a line without a pipe or another block) are `.table` lines kept verbatim; `MarkdownTable.table(from:)` and `lines(for:)` convert them to and from cells and alignments. A heading's ID (`Line.anchor`, a `HeadingAnchor`) is `{#id: x}` or `{#x}` alone on the line above it, or `{#x}` at its end (Pandoc's form), but not both: with one at its end, the line above stays text. An anchor keeps the text it was read from (`written`), so it is written back exactly while its ID is unchanged. `HeadingIDScheme` makes new IDs: `fileLevelWord` (`170_dapps_2_Setting`: the file's name, level and first word up to ten characters, then `_2`, `_3`...), `hash` (8 hex digits, FNV-1a) or `slug` (`setting-up-my-dapp`, then `-1`, `-2`...), each avoiding a set of IDs taken. Text that would otherwise read back as one of these is escaped with a backslash (`\# `, `\- `, `- \[ ] `, `` \``` `` when a closing line follows, `\{#x}` above a heading or ending one). `InlineMarkdown` reads and writes a line's `**bold**`, `*italic*`, `~~strikethrough~~`, `` `code` ``, `H~2~O` (subscript), `x^2^` (superscript), `==highlight==` and links, `[text](destination)` (`InlineSpan.link`; the destination can be any reference), as `InlineSpan`s, matching delimiters much as CommonMark does (code spans first, then emphasis with the rule of 3). Tildes pair like asterisks: a run pairs with one of the same length, except that a run of three splits into strikethrough and subscript (`~~~x~~~` is both). Subscript and superscript follow Pandoc: allowed inside words, but not across whitespace, so `x^2 + y^2` stays text. Underscores aren't emphasis. A link's text is parsed on its own (no links inside links), and a link title isn't kept. `MarkdownImage` reads `![alt](path)`, and `LinkDestination` the `(destination "title")` part both use. `HTMLComment` finds `<!-- -->` comments, which the inline parser and writer keep whole; the codec keeps a comment spanning lines with the line it starts on, so that `Line`'s text holds newlines. Tested by `MarkupCoreTests`.
- `Markup` is the app executable. `MarkupTests` drives a real `EditorViewController` through NSTextView commands (`insertText` one character at a time, `doCommand(by:)`) and the style popup's action, with manual undo groups standing in for events.

## Architecture

The app uses AppKit's document architecture. `NSDocumentController` (never subclassed) creates documents and their windows and handles the File menu, unsaved-changes prompts and quitting. Markdown (`net.daringfireball.markdown`, `.md`/`.markdown`) is the main document type. Any plain text (`public.plain-text`, handler rank Alternate) opens too, because an app that declares its own type for `.md` takes over from `net.daringfireball.markdown` on that Mac, and those types conform to plain text.

- `Info.plist` (repo root) declares the document type and names `MarkdownDocument` as its class. With no app bundle, `Package.swift` embeds it into the executable's `__TEXT,__info_plist` section with a linker flag, and that is where `NSDocumentController` reads it from. Adding a file type means editing this plist.
- `MarkdownDocument.swift` holds the Markdown read from disk, as UTF-8 with CRLF converted to LF. It owns its `EditorViewController` (`editor`, made on first use from that Markdown) and asks it for fresh Markdown when saving. The editor is shown either by a `DocumentWindowController` (the document's own window, from `makeWindowControllers`) or by a project window, never both. It has `@objc(MarkdownDocument)` so the plist can name it without a module prefix. `autosavesInPlace` is off, to keep classic Save / Save As behaviour.
- `main.swift` starts `NSApplication` by hand (there is no nib or app bundle) and sets the activation policy to `.regular`, so that a process launched by `swift run` gets a Dock icon, a menu bar and focus.
- `MainMenu.swift` builds the menu bar in code. The app menu uses the standard About panel, which reads its name, version and icon from the bundle. View > Show Markdown (⇧⌘M) reaches `EditorViewController.toggleMarkdown(_:)` through the responder chain. Menu items have a nil target and send standard selectors (`newDocument:`, `save:`, `saveAs:`, `performClose:`, `undo:`...) along the responder chain. The Edit menu has to exist for Cmd-C/V/Z/A to reach the text view. Edit > Find (⌘F, ⌥⌘F replace, ⌘G / ⇧⌘G) sends `performTextFinderAction:` with the `NSTextFinder.Action` as the tag; the text view has `usesFindBar`, so it shows the standard find bar above the text. In the Formatted view it searches the text as shown, without Markdown markers.

### Editor model

`EditorViewController` (an `NSViewController`, in the responder chain after its views) is split across files: views, invariants and undo helpers in the main file; `+Markdown` (load / save / copy); `+Styles` (popup, heading Return, typing attributes); `+Lists`; `+Shortcuts` (typed Markdown syntax); `+Emphasis` (bold, italic, strikethrough, code, subscript, superscript and highlight buttons and Format menu); `+Links`; `+Code` (code blocks, Reload Images, and `EditorLayoutManager`, which shades code blocks); `+Tables` (tables as `NSTextTable` grids); `+HeadingIDs` (hidden heading IDs, added on save); `+CrossLinks` (links to headings); `+Images` (Insert Image button); `+ViewMode` (Formatted / Markdown switch). `EditorTextView` is an NSTextView subclass that forwards marker clicks and lets the controller write the pasteboard. It also owns the spelling and grammar settings: the Edit > Spelling and Grammar toggles are NSTextView actions, which it overrides to save the settings in `checkingDefaults` and post `.markupCheckingDefaultsChanged`, so every editor sharing those defaults follows. Defaults: spelling and grammar on, autocorrect off. Tests give editors a throwaway `UserDefaults` suite. It uses TextKit 1 (`usingTextLayoutManager: false`) so the layout manager can hit-test markers.

The text view never contains Markdown markers. A line's style lives in attributes on every character of the line, including its newline:
- **Headings:** `.blockStyle` (`BlockStyle+AppKit.swift`) plus the matching font.
- **List items:** the line starts with one U+FFFC attachment character carrying `.listMarker`, which draws the bullet or checkbox (`ListItem+AppKit.swift`, drawn with a handler so colours follow dark mode). Every character of the line carries `.listLevel` and an indented paragraph style. Even an empty item therefore has a character to hold its attributes.
- **Bold, italic, strikethrough, inline code, subscript, superscript and highlight:** `.inlineBold`, `.inlineItalic`, `.inlineStrikethrough`, `.inlineCode`, `.inlineSubscript`, `.inlineSuperscript` and `.inlineHighlight` on the characters (`InlineStyle+AppKit.swift`). The font comes from the line's block style plus these (code is monospaced, subscript and superscript smaller and shifted with `.baselineOffset`), so wherever a line's style attributes are set, `applyInlineStyles(in:)` must follow to put the right font, strikethrough line, background (yellow `highlightColor` over code's shading), baseline offset and link colour back. Highlight has a Format menu item but no button (`button(for:)` is nil).
- **Links:** `.markdownLink` (the destination) on the text's characters, shown navy (`InlineStyle.linkColor`, lighter in dark mode) and underlined, with the destination as a tooltip (`+Links`). The header's link button and Format > Link (⌘K) ask for the destination and link the selection, or edit or remove the link the caret is in; with neither, the destination is inserted as the text. Typing continues a link only strictly inside it (`linkForTyping`). `NSAttributedString.Key.inlineFormatting` is every inline key, which code blocks have none of.
- **HTML comments:** each `<!-- -->` is one U+FFFC attachment character drawing nothing (`HiddenAttachmentCell`), carrying `.markdownComment`, the comment exactly as written, which saving and copying write back. A line of only comments gets `HTMLComment.hiddenLineStyle` when loaded, so it takes no space. The subscript and superscript buttons each take off the other. Typing takes the styles of the character before the caret; a button pressed with no selection is kept in `typingStyles` until the caret moves. Saving writes the styles line by line with `InlineMarkdown`, which puts spaces outside the delimiters and escapes literal `*`/`~` only when needed. Emphasis that changes mid-word (italic straight into bold) can't always be written as Markdown; the text survives but the styles may not.
- **Code blocks:** lines in the `.code` block style, kept exactly as typed: no inline styles (normalisation strips them, and the style buttons skip these lines) and no shortcuts. A non-plain fence is `.codeFence` on every character of its block, so splitting and joining lines keep it, and a change of fence between code lines starts a new block when saving. Return at the end of a code line makes another; on an empty last line of a block it ends the block. Typing ```` ``` ```` (or ```` ```lang ````) alone on a line and pressing Return starts a block. `emptyLineFence` goes with `emptyLineStyle` for an empty last code line.
- **Tables:** shown as a grid, like a word processor's: an `NSTextTable` (full width, thin borders, header shaded) with one paragraph per cell, row by row, each ending in a newline and carrying an `NSTextTableBlock` in its paragraph style, `.blockStyle` `.table`, and in the header `.tableHeader` (bold, read by `applyInlineStyles`). The delimiter row isn't shown; its alignments become the cells' paragraph alignment. Cells take inline styles. `+Tables` builds them (`tableText`, from `MarkdownTable.Table`) and writes them back (`markdownTable(of:)`, then `MarkdownTable.lines(for:)`, which pads the columns), so saving reformats a table's Markdown. `tableBlock(at:)` / `isTableLine` / `tableLines(around:)` find cells. `updateTables(in:)` re-derives every cell's block (row, column) and header from its order after each edit. `allowsTableEdit` (from `shouldChangeTextIn`) stops edits merging cells or joining a line onto one, and types a newline inside a cell as a space; NSTextView itself splits a deletion across cells into one per cell, so it empties them, while a deletion covering a whole table and text around it removes it. The header's table button (next to the link button) and Format > Table… (`insertTable(_:)`) show a popover below the button (`TableSizeController`: "Cols:", a number field with a stepper, 1–20, also stepped by the up and down keys, and an Insert button), which starts at the last number chosen (`tableColumns`, not saved across launches); `insertTable(columns:)` inserts a header and one row on the caret's line if empty, else below it. Tab / Shift-Tab select the next / previous cell; Tab in the last cell adds a row. Return adds a row; in an empty last row it ends the table. Paragraphs that form a Markdown table, typed or pasted, become one when an edit adds a newline (`convertTables`). The style popup is disabled in a cell. A table at the end of the document is followed by an empty line, so saving adds a final newline.
- **Heading IDs:** `.headingAnchor` (a `HeadingAnchor`) on every character of a heading's line, not shown (`+HeadingIDs`); the Markdown view shows them, which is where they are edited by hand. Normalisation spreads a line's anchor over the whole line, and `keepHeadingAnchorsSingle` keeps an ID on one line when a heading is split or pasted into (of adjacent lines with the same ID, the first with text keeps it). Typing attributes carry the caret line's anchor. Only headings write theirs, so a heading made a paragraph and back keeps its ID. `{#id: x}` or `{#x}` typed or pasted alone above a heading becomes its ID (`convertAnchorLine`). Saving (`MarkdownDocument.save(to:...)`, before the save starts so the Markdown view's inserted lines don't leave the document edited) calls `addMissingHeadingIDs`, which gives each heading without an ID a new one from `Settings`, unlike every ID in the document and the project's other Markdown files (`ProjectWindowController.markdownFiles()`: open documents as edited, the rest from disk). IDs already there are never changed. In the Formatted view that sets attributes without undo; in the Markdown view it inserts the text undoably.
- **Cross links:** the header's bookmark button (next to the link button) and Format > Cross Link… (⇧⌘K) show `CrossLinkController`, a popover headed "Insert Cross Link" listing headings (`crossLinkTargets()`: this document's, then, unless `Settings.crossFileLinks` is `off`, those of the project's other Markdown files, headed by file name). `link(to:)` links the selection to the heading's ID, or with no selection inserts the heading's title linked. The destination is `#id`, or with `withPath`, `other.md#id` for another file (`relativePath`, from the document's folder). A heading without an ID gets one first (`MarkdownDocument.headingID(at:settings:)`, whether or not saving adds them), which leaves its document edited; a file not yet open is opened (`MarkdownDocument(contentsOf:)`, added to `NSDocumentController` and `ProjectWindowController.adopt`, not shown).
- **Images:** `![alt](path)` (parsed by `MarkdownImage` in MarkupCore) is one U+FFFC attachment character carrying `.markdownImage`, the image's Markdown exactly as written, which saving and copying write back. View > Reload Images (`reloadImages`) replaces every image's attachment with one read from disk again. Its `ImageAttachmentCell` (`MarkdownImage+AppKit.swift`) draws the image at its actual size for now (wider images run past the window's edge), or an "Image not found" placeholder. The header's image button (`+Images`) inserts an image chosen from anywhere, by typing its Markdown and letting the shortcut convert it. `imagePath(for:)` writes the shortest path relative to one of `imageFolders` that the lookup resolves to that same file (so just the name for an image directly in one of them), or else the full path.

`load(markdown:)` and `markdown` convert between the text storage and `MarkdownCodec` lines. Copying writes list markers back as Markdown. Pasting Markdown list lines converts them through the same path as typing. The text view is still `isRichText = false`, so users can't add any other formatting.

Invariants that the controller maintains:
- **Lines stay consistent.** `textStorage(_:didProcessEditing:)` makes a line that starts with a marker carry its item's attributes throughout. Any other line gets one block style (from its first character) and no list attributes. This handles joined lines and deleted markers. It changes attributes only.
- **Typed Markdown syntax becomes styles.** `shouldChangeTextIn` records the edit and `textDidChange` acts on it (`applyMarkdownShortcuts`): `# `/`## `/`### ` → that heading (on any non-list line), `- ` → bullet, `[ ] `/`[x] ` after a bullet → checkbox, `*italic*`, `**bold**`, `~~strikethrough~~`, `` `code` ``, `~subscript~`, `^superscript^`, `==highlight==` anywhere → styled text (a just-typed closing `*`, `~`, `` ` ``, `^` or `=` waits for the next character, so `**` isn't taken as italic and what follows isn't styled; nothing converts inside inline code or after an unclosed backtick), `![alt](path)` anywhere → image, `[text](destination)` → link, `<!-- -->` → hidden comment, and stray markers inside a line are deleted. These are text changes, made through `replaceCharacters(in:with:)` so NSTextView registers the undo. They trigger only when the edit touches the syntax itself. Lines are processed top-down, so the nesting limit (at most one level deeper than the item above) sees converted lines.
- **The caret never rests before a marker.** `willChangeSelection` moves it after the marker. Moving left from there jumps to the previous line.
- **Typing attributes follow the caret's line.** They are reset on every selection change, and the popup is updated to match. An empty last line has no characters, so a style chosen there (from the popup or a typed `# `) is kept in `emptyLineStyle` for that caret location, and forgotten once the caret is anywhere else.
- **Commands:** Return (`doCommandBy`) adds a table row, continues a list (a new checkbox starts unticked). On an empty item it outdents the item, or ends the list at level 0. At the end of a heading it starts a paragraph. Tab and Shift-Tab move between table cells, or change list level. The popup turns list lines into the chosen style.
- **Every attribute change is undoable.** Changes go through `changeAttributes(in:_:)`, which registers an undo that restores the previous attributes and registers its own redo. It calls `breakUndoCoalescing()`. Normalisation and shortcuts are skipped while undoing or redoing.
- **The controller's `undoManager` is the document's.** It is overridden, and also returned to the window, so all edits mark the document edited.

### Projects

File > Open Project (`AppDelegate.openProject`) opens a folder in a `ProjectWindowController`: an `NSSplitViewController` whose sidebar item (`ProjectSidebarController`, an `NSOutlineView` source list) lists subfolders, `.md`/`.markdown` files and any other file whose type conforms to plain text (which opens as plain text), skipping hidden files and packages, and whose other pane shows one document's editor. View > Hide Sidebar is the split view controller's `toggleSidebar:`. `DirectoryWatcher` (FSEvents) reloads the outline when the folder changes, keeping open folders and the selection.

- Choosing a file opens it through `NSDocumentController` with `display: false`, so the document has no window controllers, sets `document.project`, and swaps its editor into the pane. Documents opened in the window stay open, with unsaved changes and undo, while others are shown; the sidebar marks those with unsaved changes (documents post `.markdownDocumentEditedChanged`).
- The project window controller isn't any document's window controller. Document actions (Save, Save As, Print...) reach the document shown through `supplementalTarget(forAction:sender:)`, and the window delegate returns that document's undo manager. A document's `showWindows` (File > Open of a file already open in a project) shows it in its project instead of making a window. A file that already has its own window is brought forward rather than shown in the project.
- Closing the window asks about each document with unsaved changes in turn (`canClose(withDelegate:...)`), then closes the documents.
- The project windows open at quit are opened again at launch: `applicationWillTerminate` saves each one's folder and shown file in `Settings.openProjects` (key `MarkupOpenProjects`), and `reopenProjects` opens those folders that still exist, showing the file if it still exists. NSDocumentController can't open documents in the test runner (it doesn't declare the document types), so tests can't check the file being reopened. When there are any, no untitled document is opened (`applicationShouldOpenUntitledFile`).

### Settings

Markup > Settings (`SettingsWindowController`, opened by `AppDelegate.showSettings`) edits `Settings`, which keeps app-wide settings in user defaults. Tests give it a throwaway `UserDefaults` suite.

- **Heading IDs:** `addsHeadingIDs` (key `MarkupAddsHeadingIDs`, on by default), `headingIDForm` (`MarkupHeadingIDForm`, default `idLine`) and `headingIDScheme` (`MarkupHeadingIDScheme`, default `fileLevelWord`). They apply to new IDs only, including those cross links add. `crossFileLinks` (`MarkupCrossFileLinks`): `idOnly` (`#id`, as Leanpub needs; the default), `withPath` (`other.md#id`) or `off` (only the same file's headings).
- **Images directory** (`imagesDirectory`, key `MarkupImagesDirectory`, a folder path or unset). Image paths are looked up in this folder first, then the document's own folder, then its `resources` and `images` subfolders (`Settings.imageFolders(forDocumentAt:)`).

### Printing

File > Print (`MarkdownDocument+Printing.swift`) prints the document formatted, whichever view the window is in. It builds a separate text view from the document's current Markdown with `formattedText(fromMarkdown:)`, the same conversion `load(markdown:)` uses. The view is as wide as the page between the margins, and has the light (aqua) appearance so text prints dark in dark mode.

### Markdown view

The header's Formatted / Markdown switch (`+ViewMode`) replaces the text storage with the raw Markdown, in a monospaced font, and sets `isShowingMarkdown`. In that mode `markdown` returns the text as is, and the formatting machinery is off: normalisation, shortcuts, `doCommandBy` (so Return and Tab behave as plain text), the caret-before-marker rule and the style popup. Switching back runs `load(markdown:)`. Both views have one line per Markdown line, except that a table has a line per cell in the formatted view, so the caret is carried across as (Markdown line number, distance from line end), into the start of a table's row or cell. Switching clears the undo stack, because undo steps hold ranges in the other view's text. This doesn't change the document's edited state. Copying in this view copies the text as it is.

### Plain text

A file whose extension isn't `.md` or `.markdown` (`MarkdownDocument.isPlainText`, decided in `read(from:ofType:)` by extension, because another app's `.md` type arrives as plain text) gets an `EditorViewController(plainText: true)`. It starts and stays in the Markdown view (`setShowingMarkdown` does nothing, View > Show Markdown is disabled), its header hides every control and shows a "Plain Text" label (`plainTextLabel`) instead, and `load(markdown:)` and printing show the text as it is. New documents are Markdown.
